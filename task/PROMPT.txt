请做一个安全资质覆盖审计工具，用来核对岗位能否由现有持证人合规填补。每个岗位的一个有效资质由若干类别组成，类别可有层级，持有上位类别可覆盖其所有下位。资质有持证人、授权部门、授予与终止时刻；更正通过追加事件声明替换哪个原版本，还要声明更正生效区间。以证据录入切点及实际时段作查询。岗位集合按服务组合给出同刻需求：一个人最多担任一个岗位，每个岗位席位可由同一人组合使用同一部门的多份资质，类别并集必须覆盖席位全部要求；岗位可同时要求来自两部门的双签且双方人不同。输入还列出员工排除的岗位对，例如同人控制过某关联岗位且在指定冷却区间内时禁止担任对应岗位。冷却历史来自独立的已签任记录，排程无需生成这些历史。
cover 按全部事件边界切段，求每段的完整指派和最小必要资质集，最小化使用的资质数后以按岗位、部门、人和资质 ID 排序的列表决胜。无完整指派时求最多已填席位的合法部分指派并标出空席，每岗两席须来自不同部门，允许只填一席。compare 输出旧证据与补录修订后的历史覆盖差异，含首个受影响段。测试覆盖上位类别链、跨岗位争用、同部门双签失败、冷却期结束恰可上岗及更正只改变中间一段。支持 50 人、15 岗位，须以匹配或约束搜索为主体，提供独立小规模对照。

把独立逐段覆盖扩成连续排班：各岗位可指定一种最短在岗跨度和交接限制，若席位换人，在交界时刻必须仍有与旧段, 新段都有效的第三人作为交接见证。见证要求绑定该岗位类别和独立部门，不能在同一时刻兼作其他交接或任何仍在岗席位；允许一个人跨不重叠岗位区间工作。持续在岗者遇某份资质失效可以以自己同部门的另一份有效资质继续，若缺的类别不能同刻补齐则该排班失败。所有分配以一次完整排班为目标，先最少化换人次数，再最少化各段使用的资质数之和，最后按段、岗、席位、部门、人、资质和见证 ID 决胜。compare 要指出旧证据视图已发布的最优计划在新证据视图的最早实质失效段；旧计划即使退化也不回填历史。至少测试所有段独立有解但找不到合法连续交接、交接人被两岗争用、多类别拼接资质被部分回收、以及共享员工导致全局最优不同于逐段最优。连续计划规模上限为 20 人、8 岗位、8 段。

把资质及排班示例做成本地虚构夹具，并提供可直接复现的样例。交付起点为空仓库，Windows 原生 Python 3.12 上只需标准库和 CPU。用 `python -m solution <命令> CASE.json` 查询覆盖或排班，需要持久状态时在命令上指定 `--db DB.sqlite`。任一命令的标准输出都是 UTF-8 JSON，逻辑输入相同即得到同一结果；输入结构出错时同时标识字段位置和错误码。完整的输入输出定义和复现命令写入 README，断言测试可由 `python -m unittest discover -s tests -v` 运行。
